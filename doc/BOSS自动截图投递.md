# BOSS 自动截图识别与投递

## 执行流程

在 BOSS 平台配置页启用“截图自动筛选”并保存后，每次真实任务按以下顺序运行：

1. 沿用现有搜索、城市选择和岗位去重，监听网页自然产生的详情响应以核对岗位 ID 和 HR 元数据。
2. 打开这个岗位的完整详情页，核对详情 URL 与列表选中的岗位一致。
3. 根据岗位主栏、标题区、JD 及实际滚动容器的几何位置，连续截取 1—6 张 PNG。相邻截图保留重叠，独立滚动的 JD 也会继续截取；完成后恢复滚动位置。
4. 将同一岗位的整组图片一次传入现有 `OfflineScreenshotService.analyze`。它与手动上传调用同一视觉模型、Java 字段解析器和筛选器，无需后端向本机重新上传 HTTP。
5. 岗位名称、薪资、城市、学历、公司及 JD 使用截图识别字段；自动模式不再使用原 JSON 的岗位方向和薪资判断，也不会用 JSON 静默补全缺失的截图字段。公司、岗位、招聘者黑名单及 HR 活跃过滤保留。
6. 只有处理状态 `COMPLETE` 且 Java 判断 `MATCH`、黑名单及 HR 检查也通过，才在同一详情页点击“立即沟通”，随后沿用原来的招呼语和可选图片简历流程。生成招呼语所用 JD 也来自截图。

截图前后以及模型返回后都会检查停止指令、页面安全状态和岗位 ID。停止任务或切换岗位后，不会依据旧识别结果继续沟通。视觉模型返回的是字段数据，不能指定浏览器动作。

打开完整详情前，列表选择和详情链接必须先确认属于当前岗位。详情页绑定成功后，以该详情页的岗位 URL 为核对依据；后台列表临时重绘、链接消失或暂时读不到 ID，不再被当作“已切换岗位”。若列表明确出现其他岗位 ID，或实际截图/发送的详情页变化，仍会暂停。该调整不刷新页面、不自动重复点击，也不改变识别和筛选规则。

## 首次使用

1. 在“截图识别”页保存支持图片的模型地址、模型名和独立 API Key。普通打招呼 AI 的 Key 不会自动复制过来。
2. 在 BOSS 页“截图自动筛选”面板确认并保存规则。默认沿用现有截图模块：Java/后端/服务端、实习条件、日薪 125 元/月薪 5000 元、城市不限、目标 2028 届；可以修改，毕业年份留空表示不筛届次。
3. 登录 BOSS，保存平台搜索配置，然后点击“开始投递”。后台启动本身不会开始任务。

自动规则与手动截图页面的临时规则独立。开关和规则保存于已有 SQLite config 表中的 `BOSS_SCREENSHOT_ENABLED`、`BOSS_SCREENSHOT_RULES`，不新增表。新任务开始时读取规则快照，运行中保存的修改在下次任务生效。尚未保存开关时使用 `getjobs.boss.screenshot-analysis-enabled`，当前 YAML 默认开启。关闭后恢复原详情数据筛选。

## 搜索工作类型与切换筛选

2026-10-22 根据用户在 Boss 网页选中“实习”后的实际地址，确认其工作类型参数为 `jobType=1902`。管理页“职位类型”补齐“实习”选项，保存后每次搜索携带该参数。随机城市只替换城市，工作类型保持已保存的值；“在校生”是独立的经验条件。任务开始会显示本轮工作类型。

程序等待城市、关键词、工作类型及其他搜索条件匹配本轮配置后，才接受列表容器或空结果。手动改变 Boss 网页筛选不会写回管理页；运行期间有效筛选变化会清空本轮详情缓存并暂停，防止切换加载的窗口继续处理旧卡片或使用旧识别结果。仅追踪参数、参数顺序、等价多选顺序改变不算筛选变化；后台列表短暂重绘仍沿用既有容错。需要换条件时，在管理页保存后重新开始任务。

调试/预览模式保留原有本地预览行为，不自动截图、不调用视觉模型、不发送消息；预览结果不表示截图规则已经验证。

## 点击前的鼠标移动

BOSS 的岗位卡片、搜索、沟通、输入框、发送及图片工具点击统一在点击前执行页面内的鼠标移动。默认开启 `getjobs.boss.mouse-movement-enabled`，每次随机选择 450—1100ms 的计划移动时间，使用多个带等待的中间点、弧线和缓入缓出；同一位置再次点击也有短小的移动过程。实际耗时还包括浏览器调用及原有慢速设置。

可用 `mouse-movement-min-ms`、`mouse-movement-max-ms` 调整计划时间（200—5000ms，最大值不小于最小值）；无效时间回退默认值。每段移动检查停止、安全状态，以及截图模式下已绑定的岗位身份。目标不可见、移动后布局变化或中途停止时，不会退回瞬时点击。

此功能发送浏览器页面内的鼠标事件，不移动桌面系统鼠标。打开文件选择器仍沿用原有事件监听；对于没有岗位 ID 的卡片，先完成鼠标移动，再开始监听点击产生的详情响应，避免把悬停预加载当成本次点击结果。

## 结果与异常

截图前会继续等待岗位标题、薪资、职位描述显示有效内容，并等待字体加载完成、内容与布局连续稳定至少 1 秒；每次滚动后也会重新确认稳定。默认每 500ms 复查一次，等待期间每 250ms 检查停止指令、页面安全和岗位身份，不使用整站 `networkidle` 作为继续条件。

等待、整组采集和有限重采共用 30 秒预算。采集中遇到暂时的布局变化或页面重绘，可恢复滚动位置、丢弃此前半组图片，再完整采集一次；最多重采一次，不刷新网页。完整图片组采集成功后才调用一次联合识别。安全验证、岗位身份变化、取消、持续截断或图片超限不会按临时加载问题反复尝试。

采集失败时，日志和暂停消息会显示阶段与具体原因，例如岗位描述尚未显示、字体仍在加载、布局未稳定或横向内容被裁剪，不再只显示 `CaptureException`。这些诊断不包含网页正文、完整网址或令牌。

职位描述块内部的省略号、`line-clamp` 或单行截断属于页面正常排版，截图只记录可见像素，因此不再据此中止整岗采集；只有职位描述容器自身被裁切、文字无法通过滚动显示时，才判定无法完整覆盖。

每个识别任务仍保存在 `.local/offline-screenshots/<UUID>/`，包含全部原图和 `result.json`。图片来源名称携带岗位 ID，BOSS 进度日志显示对应识别记录 ID。岗位列表中的名称、薪资及 JD 更新为视觉识别字段，已投递记录不会因为重新识别而被改成“已过滤”。字段校验失败时，`result.json` 的 `errorMessage` 和一条 WARN 日志会写明具体字段或规则（不含模型原文），便于定位是金额、长度还是枚举取值不合规。

沿用现有缺失条件按符合处理的规则：字段缺失只保留提醒，不填造事实。模型标记“识别不清”的字段按本轮规则是否依赖它分级：薪资原文、金额和计薪单位始终要求清晰；工作城市、毕业届次只在配置了对应条件时要求清晰；岗位名称、公司、职位描述、每周天数、实习时长、学历和技能只记入提醒。BOSS 页面常把长标题截断成省略号，所以标题不清不再单独判为不匹配。已明确不符或矛盾的岗位仍会过滤。`MATCH` 不表示所有条件都已得到确认。

每组最多 6 张、单张 8 MiB、合计 24 MiB、单张 1600 万像素。内容尚未覆盖完但已达上限、有限复查后仍无法完整采集、模型不可用/失败、识别忙碌或保存失败，都会暂停本轮，不用半组截图继续沟通。模型调用不自动重试，并有既有请求时限；点停止后可能需要等待在途请求返回，但返回后会先检查停止指令。

更新源码和静态页面后需停止旧后端、重新运行并刷新管理页面。离线单元测试不启动招聘站浏览器、不调用真实模型、不向 HR 发消息；真实网站布局和实际模型连通性仍需在正常使用中核对。
