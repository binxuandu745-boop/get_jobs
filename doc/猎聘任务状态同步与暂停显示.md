# 猎聘任务状态同步与暂停显示

2026-10-14：本次只修复管理页自动显示任务暂停，不增加手动断点暂停，不修改沟通确认条件，不重发消息、不更改真实数据库的待确认记录。

## 原因与改动

原页面只有登录状态 SSE；点击开始后，在前端将运行标记设为 true，后端保护暂停或正常结束不会更新这个标记。因此“停止投递”按钮可能在任务已结束时仍然显示。

现在页面每 2 秒读取一次本机 `GET /api/liepin/status`，首次打开、回到页面、手动刷新和操作后也同步。查询串行执行，超时 5 秒；失败显示“状态未知”，不声称任务已经结束。此轮询不调用招聘网站，不会自行开始、停止或重新投递。

页面显示“启动中 / 运行中 / 已暂停 / 未运行 / 状态未知”。保护暂停时显示橙色原因、原因代码和后端说明，不保留错误的运行按钮。刷新页面也会重新获取当前后端状态。暂停信息是当前 Java 进程内状态，不是跨服务重启持久化的任务历史。

开始请求在提交异步任务之前同步发布 `starting`，执行入场后转为 `isRunning`；提交被拒绝则按请求身份恢复原暂停说明，防止旧请求覆盖新任务。结束后清理 busy，保留保护暂停原因。状态未知或任务活动时不能从管理页退出登录，避免误清运行中使用的登录信息。

开始、停止、退出仅由用户点击触发；POST 与后置状态核对全程互斥，不自动重试 POST。后置状态查询失败也不把请求当作未发生。

## 使用

在 IDEA 停止旧后端后重新运行源码，再刷新管理页面。未打包或替换运行 JAR，也未自动重启应用、浏览器或投递任务。旧前端生成资源在同步前已备份到 `.local/liepin-task-status-frontend-backups/`。

看到“已暂停”时先核对原因，不需要再点停止。点击“重新开始”是新一轮任务，不是从原位置断点继续；沟通待确认记录仍然不会自动重发。

## 离线验证与剩余事项

746 项 Java 离线测试、14 项前端状态测试通过，TypeScript 与静态构建通过。测试覆盖启动请求拒绝回滚、异步启动窗口、重复提交、启动中停止、自动暂停、轮询超时、错误响应、卸载中止及操作后核对。未运行实际招聘网站端到端测试。

“聊天里已有消息但程序仍未确认”的问题暂未改：现有观察器仍只读同岗位卡片的“继续聊”信号。需要用户提供已发送消息及同一聊天窗口岗位信息的脱敏 DOM 片段，再核对新的确认条件。不能把本次前端修复理解为沟通确认已修好。

## 如何提供聊天 HTML

先不要发送新消息或刷新猎聘页面。在已发出的消息气泡上右键，选择“检查”（Inspect）；浏览器会打开开发者工具，并高亮对应元素。

如果不熟悉元素面板，先截图开发者工具高亮的几行 HTML，下一步再指导选择哪一个父容器，不必复制整页。

最终需要两部分：消息气泡的外层结构，以及同一聊天窗口中岗位信息的结构（最好包含 `/job/数字ID.shtml` 链接或明确岗位 ID）。在元素面板中对选定容器右键，选择 Copy → Copy outerHTML，粘贴成 TXT 后上传。

保留标签、class 和岗位 ID 相关属性。姓名、联系方式和聊天正文可以替换为占位文字；不要提供整页 html/body、Cookie、Local Storage、请求头、登录令牌或验证码。不在开发者工具 Console 执行脚本。
