# 猎聘、前程无忧和智联招聘基础配置

SQL 文件：同目录 `多平台基础配置.sql`。

目标数据库是 `get_jobs/db/getjobs.db`，使用 SQLite。请在 DataGrip 的 `getjobs` 数据源控制台执行整个 SQL 文件，不在 MySQL 连接执行。

## 预设内容

| 平台 | 地区条件 | 项目读取的薪资值 | 期望搜索范围 |
| --- | --- | --- | --- |
| 猎聘 | 空字符串，不指定地区 | `4.5$20` | 4500～20000元/月，网站端尚未实测 |
| 前程无忧 | `[]`，不指定地区 | `["04","05","06","07","08"]` | 本机选项表的4.5～6千、6～8千、0.8～1万、1～1.5万、1.5～2万 |
| 智联招聘 | `0`，不限 | `4500,20000` | 4500～20000元/月，网站端尚未实测 |

关键词：Java后端实习、Java实习、Java后端开发、Java开发工程师、Java后端研发、Java服务端开发、Java服务端研发。每个词分别搜索；不设置必须包含“实习”的硬限制，避免遗漏名称不同的Java岗位。现有三平台没有独立的岗位方向复核或在校身份筛选，需人工查看岗位要求。

你已于2026-10-13确认另外三个平台按4500～20000元/月配置，已执行SQL并读回核对。这样可与前程无忧界面最多5档的限制保持一致。超过20000元的岗位不在本预设范围中；若希望覆盖更高档位，须同时调整该平台档位，而不是只改一个最大值。

猎聘按前端示例的“最低千元$最高千元”格式填写，智联按前端的“最低元,最高元”格式填写。程序能读取这些字符串，但尚未验证网站是否接受猎聘小数下限，或搜索结果是否严格按区间下限筛选。这些是搜索条件预设，不等于已实现逐岗位的4500元本地硬过滤。

## 执行和验证

生成时三个配置表均为空；脚本支持为空时新增，已有记录时仅更新第一条，不删除其他记录。执行前请确认薪资上限，若已有自己设置的条件，请先检查脚本将更新哪些值。

先验证51job档位与本机选项表一致；不一致时该校验语句报错。若DataGrip报告错误，请执行 `ROLLBACK;`，排查后再重试，不手动继续后面的更新。

脚本最后只查询三个配置表，显示关键词、地区和薪资预设。不会读取或输出API密钥、Cookie、简历、聊天记录。

执行后刷新对应管理页面即可查看配置。写入配置不会启动投递。**2026-10-13已写入真实数据库，猎聘、前程无忧、智联的配置表各有1条记录，关键词、地区与薪资值均已用新的只读连接核对。**

已使用本机数据库的表结构和51job选项，在内存数据库完成首次执行、重复执行不新增记录、保留其他配置记录、保留BOSS/密钥/登录记录，以及错误档位阻止写入这5类检查，全部通过。这是SQL和配置结构验证，不是招聘网站实际运行验证。

## 当前项目的范围

- BOSS条件保持原来的最低5000元，此脚本不修改BOSS配置。
- 真实毕业年份是2028届，三个配置表没有毕业年份字段；没有写入2027或虚构在校身份。
- 现有启动配置为 `getjobs.browser.boss-only=true`，其他平台页面尚不会被初始化。填好配置不等于其他平台已经能运行；启用前还要调整启动模式、分别登录和验证链路。
- BOSS新增的最低薪资复核、3000～5000毫秒步骤等待、保护性暂停和后台页优化方案，不会因这份SQL自动应用到其他Worker。
- 没有修改AI介绍、提示词、模型或API密钥。其他平台是否调用AI、如何发送招呼，应分别核验，不能从BOSS的功能推断。

此次仅生成和执行基础配置SQL，没有启动浏览器或投递任务。
