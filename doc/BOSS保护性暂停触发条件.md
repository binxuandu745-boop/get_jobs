# BOSS 保护性暂停触发条件

适用于 2026-10-13 修改后的项目源码。旧运行 JAR 不会自动获得这些修改；需要在 IDEA 停止旧进程并重新运行源码。本次没有启动浏览器或投递。

## 判断依据

| 情况 | 处理 | 是否确认出现安全验证 |
| --- | --- | --- |
| 地址路径是已有验证路径，或页面出现可见的“安全验证”、验证按钮、验证码面板 | 本轮检查发现后立即暂停本次任务，显示置顶提醒，交由用户手动处理 | 是，`SECURITY_VERIFICATION` |
| 页面还在加载，验证元素不存在，或 AI 生成耗时较长 | 不因为耗时长、缺少验证元素而判断出现验证 | 否 |
| 页面检查遇到短暂 URL/DOM/失效对象异常 | 最多检查 3 次，失败轮次之间各等待 500ms；恢复后继续，只读复查，不刷新、导航或代办验证码 | 否 |
| 页面检查 3 次均失败 | 暂停，原因包含次数和异常类型，属于 `JOB_DETAILS_UNAVAILABLE` | 未确认 |
| 当前页面不存在或已被关闭 | 暂停，提示页面不可用；没有必要反复等待一个已关闭的页面 | 未确认 |
| 选中岗位后，详情响应暂时没有到达 | 继续等待原请求，默认响应等待上限 60000ms；等待中检查取消和验证，不重复点击该岗位 | 否 |
| 响应等待达到上限，页面仍没有明确验证信号 | 暂停并明确报告“岗位详情读取超时”，属于 `JOB_DETAILS_UNAVAILABLE`，不是“检测到风控” | 未确认 |
| 已返回的详情响应为非 2xx、空内容、无效 JSON 或缺少岗位名称 | 暂停为数据读取失败，不持久化空岗位、不标成“不符合条件”、不发招呼 | 未确认，仅根据 HTTP 状态不能认定验证码 |
| 卡片没有详情链接，且返回的详情也拿不到可核对的岗位标识（短卡片、推荐位等） | 只跳过这一个卡片并继续下一个岗位：日志和进度用独立标签“岗位标识缺失”说明原因，不记录、不沟通、不暂停整轮 | 否 |
| 截图模型接口成功，但返回的 JSON 不合规（`INVALID_EXTRACTION`） | 只跳过该岗位并继续下一个：`result.json` 和 WARN 日志写明字段级原因；模型多返回的未支持字段直接忽略 | 否 |
| 点击“立即沟通”后，同一标签页跳到该岗位的聊天页 | 视为同一岗位继续发送：点击前仍只接受详情地址；聊天地址带 `jobId`/`encryptJobId` 时必须与当前岗位一致。其他岗位的聊天页、其他站点或非聊天页面仍然暂停 | 否 |
| 沟通进行中后台列表重绘、`more-job-btn` 链接暂时读不到 | 沟通阶段不再反复读后台列表（只核对已绑定的详情页/聊天页与页面安全），避免列表重绘时按默认 30 秒超时静默卡住；投递目标由已打开的详情页决定 | 否 |
| 仅公司名称缺失，但岗位关键数据有效 | 不仅凭公司名称为空暂停；保留原有警告及业务筛选 | 否 |
| 用户停止任务或线程被中断 | 取消，不把用户取消包装成验证码或保护性暂停，不继续发送 | 否 |

已有验证路径为 `/web/user/safe/`、`/web/passport/zp/verify`、`/web/passport/zp/security` 及路径中的 `security-check`；仅搜索参数包含这些词不会触发验证判定。可见验证元素使用精确文字/面板选择器，不按岗位描述里的模糊词语或响应时间判断。

## 慢响应与安全验证分开

- 三次页面检查之间最多有两次 500ms 等待；这不是整页加载时限，也不保证底层浏览器调用每次都能在 500ms 内返回。
- 详情响应上限由 `getjobs.boss.detail-response-timeout-ms` 配置，当前是 60000ms。有效范围为 1000～120000ms，无效配置回退到 60000ms。它不是整个岗位处理或 AI 调用的总时限。
- 新的等待只监听本次选择后的详情请求，排除旧请求的迟到响应；临时监听器在结束时移除，不注册无限重试或后台循环。
- 完整详情导航等待 `DOMContentLoaded`，最多 45 秒；若导航等待报错但已到达目标详情地址、页面检查正常，则继续检查沟通控件，不仅因为导航耗时长而暂停。若未到达目标地址，则按读取失败暂停。
- 步骤等待中的失效对象/执行上下文销毁异常，在只读复查正常后继续等待；正常步骤随机延时、AI 开关和招呼内容没有被此次修改改变。
- 所有文本或图片发送动作前仍进行页面检查。实际出现验证时不会自动刷新绕过，也不会把发送结果不确定的消息自动重发。

## 提醒与恢复

两种暂停原因都会尝试显示 Windows 桌面置顶提醒。点击“知道了”只是关闭提示，不会恢复任务；需检查页面后手动开始。没有图形桌面或提醒关闭时仍保留暂停状态和日志。

本次修改降低单次暂态错误造成的误停，但不承诺永久无误判：持续读取失败、返回无效数据或超过明确上限时仍会停止。这些技术失败与“已确认出现安全验证”保持不同分类。

## 不符合条件岗位的等待优化

2026-10-13按用户确认，将原“读取岗位详情”的随机等待移到所有业务筛选通过之后，日志名称改为“筛选通过，继续处理岗位”。详情已经返回时不再先人为等待再过滤：方向/实习配置、薪资、岗位黑名单、HR活跃度、公司黑名单、招聘者黑名单中任意一项不通过，都直接跳过这一段等待。符合条件的岗位仍保留该等待，下一岗位点击前的等待也保留。

没有改随机等待的上下限、业务筛选规则、AI开关、数据记录方式或保护性暂停条件；过滤前的取消及安全检查没有移动或删除。这次没有增加列表卡片预筛，仍以已校验的详情数据为准。

源码编译与216个离线测试全部通过，失败/错误/跳过均为0。测试使用模拟浏览器与消息，不会发送真实招呼。覆盖慢响应恢复、暂态探测恢复、真实验证优先、等待中取消、无效数据不入库、旧请求迟到、监听器清理、六类过滤不等待及匹配岗位保留等待等情况；真实招聘网站行为仍需在用户启动后的正常使用中核对。没有打包、更换运行JAR或自动重启用户进程。
