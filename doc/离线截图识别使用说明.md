# 离线岗位截图识别

> 手动上传入口保持独立。现在也可在 BOSS 页启用自动截图，复用本模块识别能力并接入投递，详见 [BOSS自动截图投递](BOSS自动截图投递.md)。下文“不点击沟通、不发送招呼”指手动上传接口自身。

## 功能范围

手动选择同一岗位的1至6张已保存 PNG/JPEG 截图 → 一次视觉模型请求合并提取字段 → Java 校验和筛选 → 保存全部原图及一份判断结果。

本模块不打开招聘网站、不截取网页、不调用 Playwright、不点击沟通、不发送招呼、不改任何平台的投递开关。

## 页面与首次配置

重启更新后的后端并使用更新后的前端，在左侧选择 **截图识别**，页面路径 `/screenshot-analysis`。

1. API 地址和模型默认参考现有环境配置的 `BASE_URL`、`MODEL`，可在本页面单独修改。
2. 在密码输入框粘贴本模块的 API Key 并保存。截图模块不会自动读取旧的 `API_KEY`。不要将密钥发到聊天、URL或截图中。
3. 已保存的密钥只显示“已配置”，服务器不会把旧密钥返回给页面。再次保存时密钥留空表示保留；清除按钮只清除本模块的密钥。
4. 模型必须支持图片输入。当前 DeepSeek 官方文档确认 `deepseek-flash` 支持图片，见[图像理解说明](https://api-docs.deepseek.com/zh-cn/guides/vision/)。其他服务需提供相同格式的多模态 Chat Completions 接口，不能把仅支持文本的模型当成视觉模型。

独立配置键：

| 键 | 用途 |
| --- | --- |
| `SCREENSHOT_AI_BASE_URL` | 截图识别服务地址 |
| `SCREENSHOT_AI_MODEL` | 支持图片的模型名 |
| `SCREENSHOT_AI_API_KEY` | 截图识别专用密钥 |

配置保存在现有本机 SQLite 配置表中，沿用项目已有存储机制，不应提交或分享 `db/`。本模块不会改动原来的打招呼配置。HTTPS服务地址不能含用户名、密码、查询参数或fragment；本地测试模型可使用HTTP回环地址。不接受招聘网站地址作为模型接口。

## 使用

同一岗位可选择 **1至6张** PNG/JPEG 截图，单张不超过 **8 MiB、1600万像素**，总大小不超过 **24 MiB**。页面支持追加、上移、下移和移除图片，按岗位详情从上到下排序后识别。图片集合或顺序变化后，需要重新勾选本组图片的发送同意。

对于详情超出一屏的岗位，先自行保存顶部，再向下滚动岗位详情区域保存后续内容。相邻图片可以保留一小段重叠文字，以便对齐；确保图片来自同一个已选中岗位。无需拼接成长图。固定滚动像素不能从静态截图准确推断，因为窗口大小、缩放和详情内部滚动区域都会影响实际可见内容。本模块不自动滚动或操作浏览器。

模型会在一次请求中接收按顺序标注的独立图片，合并当前岗位的职责、要求、薪资等信息，去除重复内容和吸顶标题，忽略左侧列表等其他岗位卡片。第二张出现的要求同样参与Java筛选。若可见标题、薪资等内容矛盾或明显来自不同岗位，模型须标记为不确定，Java按不符合处理；该检查依赖模型正确识别，无法保证识别出所有混图情况。

图片可能包含姓名、头像、聊天内容等个人信息，请先确认允许将这些内容提供给所配置的模型服务。模型可能按token收费，每次主动识别均可能计费。前端防连点、后端同一时刻仅接受一个识别任务；模型失败不会自动重试。

默认筛选条件：Java/后端/服务端方向、实习优先、最低125元/天或5000元/月、不限制城市、目标2028届。条件在截图页面独立设置，不改变BOSS等平台的配置。清空目标毕业年份表示不按届次筛选。

| 结论 | 含义 |
| --- | --- |
| `MATCH` | 按本次规则符合条件；缺失字段直接按符合处理，仍保留原始空值和提醒，不代表缺失事实已获确认 |
| `MISMATCH` | 明确不符合、识别内容矛盾/不清、完全无法识别，或模型调用/解析失败，均按不符合处理 |
| `REVIEW` / `ERROR` | 仅兼容旧记录的筛选结论；新识别不再因普通缺失字段进入待确认 |

当前缺省处理口径由用户确认：部分信息已识别时，未提供或未提取到的薪资、届次、城市、岗位名称等字段，直接认为对应条件符合；不填造字段值。例如没有毕业届次时，原始 `graduationYears` 仍为 `[]`，但不因此排除。面议、待定等未提供数值的薪资同样作为金额缺失处理。

已识别的明确不符合仍排除；薪资原文与结构化金额/单位矛盾、模型标记已出现文字读不清（`uncertainFields`）、无任何实质识别信息的空对象，均按不符合处理。缺失不是识别错误：模型只把已经出现却模糊、截断或冲突的字段列入 `uncertainFields`。

若薪资原文能明确解析出金额与单位，Java仍使用原文作阈值比较，即使模型漏填结构化金额/单位，也不能把原文已明确的低薪放行。这只用于本地比较，不会回填原字段；双方均缺计薪单位时不做日薪月薪猜测或换算。

处理状态和筛选结论是两件事：模型调用或解析失败仍保留 `status=ERROR`、错误代码和原因，同时 `evaluation.decision=MISMATCH`，表示按规则排除，不是声称岗位本身已被验证不合格。无效图片会直接拒绝上传，不会当作符合。

Java会核对薪资原文、数值与日薪/月薪单位，但不能自动发现所有视觉误读；未检测出的错误仍可能影响判断。请保留原图以便核对。截图内文字被视为待提取的数据，而不是可以执行的指令。所有结果仍仅供本地筛选，不代表已投递或录用。

## 保存位置

每次有效截图识别产生一个 UUID，文件保存在项目目录：

```text
.local/offline-screenshots/<UUID>/
  source.png 或 source.jpg  # 原始上传字节，不修改图片
  source-2.png 或 source-2.jpg # 第二张；后续依次为source-3至source-6
  result.json              # 结构化字段、结论、原因、模型与错误信息
```

结果包含 `sources`（按顺序记录每张图片的 `index`、文件名和SHA-256）和 `imageCount`。旧的 `sourceName`、`imageSha256` 保留为首张图片信息，旧版单图记录仍可读取。原图保持上传字节不变，不包含API Key、base64图像或未经处理的模型响应。此目录已加入 `.gitignore`。失败记录也会保存整组原图与来源信息，便于区分“模型没识别成功”和“岗位不匹配”。保存结果并不等于成功投递。

## 本地接口

仅允许回环来源和本机Host。修改配置及上传需要 `X-Offline-Screenshot: 1` 请求头；上传还需要 `consent=true`。不提供任意本地路径读取或远程图片URL输入。

- `GET /api/offline-screenshots/config`：公开配置与密钥是否已配置，不回传密钥。
- `POST /api/offline-screenshots/config`：JSON `{baseUrl,model,apiKey?,clearApiKey?}`。
- `POST /api/offline-screenshots/analyze`：multipart重复的 `files` 字段（按顺序1至6张）、`consent=true`、可选 `rules` JSON。兼容旧的单张 `file`；不能同时提交 `file` 和 `files`，旧 `file` 不接受重复提交。
- `GET /api/offline-screenshots/results/<UUID>`：读取已有识别记录。

上传示例（请将文件名替换为实际截图，不要在命令行粘贴API Key）：

```powershell
curl.exe -H "X-Offline-Screenshot: 1" -F "consent=true" -F "file=@C:\Users\lenovo\Desktop\job.png" http://127.0.0.1:9527/api/offline-screenshots/analyze
```

同一岗位上下两屏示例：

```powershell
curl.exe -H "X-Offline-Screenshot: 1" -F "consent=true" -F "files=@C:\Users\lenovo\Desktop\job-top.png" -F "files=@C:\Users\lenovo\Desktop\job-bottom.png" http://127.0.0.1:9527/api/offline-screenshots/analyze
```

整组图片先通过大小、格式和解码校验，再发起一次AI请求；任一原图损坏会直接拒绝整组输入。调用失败不会改成逐张重试，也不会只用第一张的部分结果假装整组识别完成。

前端中止等待不保证已发送给模型的请求被取消，也不保证退款。不要因等待较久就连续重新提交。

## 验证边界

单元测试使用模拟模型、测试图片及临时目录，不启动招聘浏览器、不发送招呼、不消耗真实API额度。实际模型连通性需要你在新页面保存Key后，用一张允许发送的图片验证；未真实调用前不应把模拟测试通过写成API已经联调成功。

更改筛选规则不会重写旧的 `result.json`。需要使用新规则时，对同一张原图主动重新识别会生成新记录，也可能产生新一次API费用。更新源码和静态页面后需重启后端、刷新页面，运行中的旧Java进程不会自动采用新规则。
