# 猎聘步骤延时与快速跳过

2026-10-13按用户要求，将BOSS的可配置步骤节奏和过滤后快速跳过思路接入猎聘；后续经用户确认，启动模式改为仅猎聘。此为源码与配置改动，不是真实投递验证。

## 登录检测与步骤间隔不是一回事

原来的后台登录检查仍是 `@Scheduled(fixedDelay = 3000)`，只在猎聘页面已经初始化、监控未暂停且Playwright线程空闲时尝试执行。3秒不是每条岗位的投递间隔；刷新管理页也不会强制执行页面探测。

源码及外置配置均设置 `getjobs.browser.platform-mode=liepin`。显式模式优先于旧的 `boss-only` 开关，只创建、初始化猎聘页面，不创建BOSS、51job或智联页面；不因模式切换自动启动投递。本次没有启动或重启现有进程、浏览器，也没有扫码或投递。

可选模式为 `boss`、`liepin`、`all`。未配置新字段时沿用旧开关；非法模式直接报配置错误，不会启用全部平台。初始化判断按选定模式检查对应页面，不再要求必须有BOSS页面。

猎聘登录探测只读取官方页面URL及明确可见的用户/登录标志，不导航到登录页、不点击扫码切换、不用缺少登录按钮推断“已登录”。页面加载中、读取异常、安全验证页统一为待确认；待确认不清除已有会话，但不允许据此自动发送。持久化目录继续复用，数据库的旧Cookie快照不再注入覆盖当前登录。

管理接口 `POST /api/playwright/check-login` 按已启用平台只读复查；也可使用 `POST /api/liepin/check-login`。运行任务或Playwright忙时跳过手动复查，不阻塞投递。复查不会初始化、重开浏览器或发起沟通。同一程序管理的浏览器内，在另一官方标签页完成登录可被重新绑定；不会复制其他浏览器的登录信息。

## 配置与流程

| 配置 | 当前源码YAML | 现有运行包外置YAML |
| --- | --- | --- |
| `getjobs.liepin.action-delay-min-ms` | 2000 | 3000 |
| `getjobs.liepin.action-delay-max-ms` | 4000 | 5000 |
| `getjobs.liepin.required-role-terms` | Java、后端、服务端 | 相同 |
| `getjobs.liepin.require-internship` | false | false |
| `getjobs.liepin.minimum-monthly-salary` | 4500元/月 | 相同 |
| `getjobs.liepin.minimum-daily-salary` | 125元/天，独立检查薪资区间下限 | 相同 |
| `getjobs.liepin.communication-confirm-timeout-ms` | 15000，只读确认沟通整体预算 | 相同 |

源码与外置配置分别沿用各自BOSS现有的等待范围，不覆盖用户之前修改的BOSS配置。组件无配置时默认随机3000～5000ms；非法范围回退默认值。最终采用实际启动时加载的配置。

实际搜索、翻页、处理符合条件的卡片、点击“聊一聊”前分别等待。等待按不超过250ms分片，检查用户取消和页面状态，不使用随机等待去绕过平台验证。

猎聘与BOSS页面流程不同：本次没有添加AI生成或额外自动发消息流程。旧实现假定点击“聊一聊”会触发站点自动招呼；新版不据此宣称发送成功，仅通过同岗位明确的“继续聊”按钮确认已建立沟通，不证明招呼或简历送达。

## 快速跳过的判断

先从卡片提取jobId，再对应同ID的接口快照；不再用列表下标取数据。ID可来自既有卡片埋点或 `/job/数字ID.shtml` 等岗位链接。找不到对应数据时记录“待确认”，不会用“岗位/公司”占位文字继续沟通。

标题明确不符合方向、明确低于月薪4500元或日薪125元下限，或已有投递/结果待确认记录时，直接跳过该卡片，不滚动、不悬停、不进入处理/沟通等待、不点击聊天。标题缺失、薪资格式或单位不明时，也不发送，日志记录“待确认”。薪资事实不明的日志与已经预留发送机会的数据库待确认状态不是同一种记录，不会仅因薪资面议把数据库置为2。显式把日薪门槛设为0时仍拒绝日薪，不按出勤天数猜算月收入。

没有新增实习硬限制，没有变更搜索关键词或城市，没有修改数据库账号、API密钥或数据库里已有的Cookie备份。`require-internship=false`允许符合其他条件的正式岗位进入候选，是否接受2028届在校生仍需人工核实。

数据库既有的 `delivered` 状态通过已有批量查询回填到内存，不增加逐条查询或覆盖旧记录。两个等待阶段后都会再次核对卡片jobId；列表换序时跳过本次动作，避免点击与已评估岗位不同的卡片。

## 安全、取消与计数边界

页面状态检查仅只读，明确验证URL或可见验证提示才归为安全验证暂停。普通加载中、验证元素未出现不会据此判定验证；短暂读取异常最多3次500ms间隔复查，持续失败或页面关闭按技术问题暂停。公开验证码路径参考[猎聘安全中心入口](https://safe.liepin.com/intercept/ip/captcha/dispatch)，DOM定位尚未在用户实际网页中验证。

用户取消或保护暂停会穿透内部的滚动、悬停、按钮查找和关窗异常处理，结束当前任务，不继续下一卡片。鼠标微调遇到线程中断时保留中断标记并取消，防止异常被忽略后继续点击。

任务状态增加 `paused`、`pauseReason`、`lastMessage`；暂停发error，取消发warning，不报告正常完成。保护性暂停不会自动重开浏览器、重试发送或代办验证码。

## 沟通结果与防重复边界

2026-10-13经用户确认，修正原有“点击/聊天加载失败仍标为已投递”的乐观记账。复用 `liepin_data.delivered`，不新增表或修改真实数据库历史记录：

| 值 | 含义 | 自动处理 |
| --- | --- | --- |
| 0或NULL | 尚未沟通 | 满足筛选且成功预留后才可点击 |
| 2 | 已预留，操作结果待确认 | 快速跳过，不自动重发或重置0 |
| 1 | 旧版已投递记录，或新版确认已建立沟通 | 快速跳过；不代表HR已收到招呼/简历 |

流程为：筛选和最终ID核对 → 单条条件UPDATE并提交0/NULL到2 → 再次核对卡片和“聊一聊”按钮 → 仅点击一次 → 最多15000ms只读观察同jobId的可见“继续聊”完整文本 → 条件UPDATE 2到1并确认成功 → 增加本次确认计数 → 清理聊天窗口。

预留失败/记录不存在不点击；数据库异常以 `RECORD_STATE_UNAVAILABLE` 暂停。已经点击但超时、同ID证据不足或读取失败，以 `COMMUNICATION_UNCONFIRMED` 暂停并保留2，不计成功、不自动重试、不继续下一岗位。本人取消和安全暂停仍穿透，已有2不会回退0；写1失败也不新增成功计数。普通快照刷新不写投递状态，避免覆盖预留记录。

确认观察每轮重新按jobId找卡片，不把聊天头部出现当作消息送达；读取超时短于250ms并在每次调用前后检查整体预算、停止与验证。同步浏览器传输本身无法由这层代码硬中断，但预算过后返回的证据不会被接受。

已经确认并成功写1后，等待聊天头部或关闭按钮的普通异常仅是清理警告，不改计数、不重复发送。日志分别标注“等待聊天界面”或“关闭聊天窗口”，不再统称关闭失败并假定投递成功。已有“继续聊”的岗位只读核查后可同步已建立沟通，不点击，也不计本次新动作。

分析页面、CSV、筛选及统计增加“待确认”。历史1不会自动回退或被重新认定为新版本已验证；尤其是旧日志里超时但已标1的那条，仍须本人查看平台消息。没有自动重置或重新投递入口，也没有新增服务端送达确认。
