# 浏览器模式单选切换

2026-10-13，按用户确认改为四个互斥网站选项。入口位于管理页左侧导航的“浏览器模式”。

## 使用

1. 选择BOSS直聘、猎聘、51job或智联招聘，每次只启用一个网站。
2. 点击“切换”，阅读会重新打开助手浏览器的提示，再点“确认切换”。单选、刷新管理页及普通导航不会自行切换。
3. 等待当前模式和“已就绪”状态确认；目标网站可能仍需要本人登录。切换不会启动投递。

首次更新需在IDEA停止旧进程并重新运行源码、刷新管理页。以后正常切换不用改YAML或重启Java服务，但会关闭并重新打开这一个助手浏览器。不要使用旧的运行JAR判断新功能是否生效。

保留项目独立的持久化登录目录，不清除会话或投递记录，不复制其他浏览器的登录信息，也不保证平台不会要求重新登录。旧页面资源已备份到 `.local/browser-mode-frontend-backups`，未打包或替换JAR。

## 状态与存储

| 选项 | API/存储值 | 单独初始化 |
| --- | --- | --- |
| BOSS直聘 | `boss` | BOSS页面 |
| 猎聘 | `liepin` | 猎聘页面 |
| 51job | `51job` | 51job页面 |
| 智联招聘 | `zhilian` | 智联页面 |

显式选择写入SQLite已有config表的 `BROWSER_PLATFORM_MODE`，只访问这个配置键。程序重启后先恢复保存的选择；没有保存时才采用 `getjobs.browser.platform-mode` 的启动默认值和旧 `boss-only` 开关。YAML不是每次切换都被改写。

旧 `all` 配置保留读取兼容，但前端不提供“全部平台”选项；遇到旧配置会显示提示且不自动勾选替代项，需本人选择一个网站。`51job`是规范值，不写成`job51`。

## 保护

- 任一平台任务在运行、任务已预约但异步执行尚未开始，或浏览器调用已排队时，拒绝切换。前端忙碌状态禁用切换，后端也独立检查。
- 切换和投递启动共用提交保护，避免“前端刚检查空闲，后台投递刚启动”的竞态。切换期间不接收新的投递任务或其他前台浏览器调用，后台探测跳过。
- 保存新选择成功后才关闭旧助手浏览器。保存失败保持原浏览器；初始化失败保留已保存的目标选择，显示未就绪，可由用户再次确认重试。
- GET状态只读，不初始化或重开浏览器。POST请求超时或断开不一定停止后台切换；前端只重新读取状态，不自动重复POST。
- 主动选项和确认目标不被轮询覆盖；切换成功提示需由POST及后续GET共同核验，不能凭HTTP成功就忽略未就绪状态。
- 切换后旧页面的导航回调和51job登录等待线程不再探测旧页面。关闭窗口会清空运行时登录状态，但不清理持久化会话。

接口：`GET /api/playwright/status`；`POST /api/playwright/platform-mode`，JSON形如 `{"mode":"boss"}`。非法选择返回400，忙碌返回409，存储或初始化失败返回500。错误中不包含输入的原始配置值、密钥或原始数据库错误。

源码编译与716个离线测试全部通过（失败/错误/跳过均0）；前端类型检查和静态构建通过。覆盖四个单平台页面创建、独立初始化、持久化优先级、规范值、无操作、忙碌、并发预约、失败清理、登录状态失效和控制器错误码。
